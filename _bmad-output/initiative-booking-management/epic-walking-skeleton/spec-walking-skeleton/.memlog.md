- (direction) Express mode; slug walking-skeleton; spec lives in its epic folder (developer, 2026-10-09)
- (decision) Why: prove the sandbox pipeline delivers a full vertical slice (API + UI + tests + CI) through the PR loop before product features, and give architecture work a real codebase (Option C, session 005)
- (decision) Azure and any deployment are out of scope for Epic 0; a later epic owns them (developer, 2026-10-09)
- (constraint) Stack per ADR-0003/0005/0006: .NET 10, Angular 22, monorepo src/backend + src/frontend + tests/backend, root SlotBook.slnx, xUnit v3 + Shouldly, Vitest/jsdom, npm; test commands: dotnet test (root), npm test in src/frontend
- (constraint) No database, persistence, auth or tenancy in Epic 0
- (constraint) Backend is a single API project; no Clean Architecture layers or modules until the architecture doc and ADR-0002 decide them
- (constraint) Frontend and backend share only the HTTP contract; neither references the other's folder (ADR-0006)
- (constraint) Each story is one PR built in one sandbox run (ADR-0004); all tests must run in the sandbox: no browser, no external services
- (constraint) Generic naming only (client-IP firewall): product name SlotBook, no client branding
- (capability) CAP-1 intent: an operator or probe can ask the API whether it is alive. success: GET /health returns 200 with JSON {"status":"Healthy"}; an integration test (WebApplicationFactory) asserts status code and body
- (capability) CAP-2 intent: a visitor opening the web app sees whether the API is reachable. success: the page shows a healthy state when /health answers 200 and an unavailable state on error or non-200; component tests cover both with HTTP mocked
- (capability) CAP-3 intent: the developer runs both sides locally and sees the frontend reach the API. success: from a clean clone, the README steps (dotnet run, npm start) give a browser page showing the healthy state
- (capability) CAP-4 intent: every PR is built and tested automatically for the side(s) it changes. success: a PR touching only src/frontend runs only the frontend checks (and vice versa); a failing test turns its check red
- (assumption) /health is at the API root (not under /api), liveness only, since there are no dependencies to check
- (assumption) Local run uses the Angular dev-server proxy to reach the API, so the API carries no CORS config in Epic 0
- (assumption) Files generated by the Angular CLI and dotnet new templates do not count toward the ~10-file story size limit
- (question) Required checks: path-filtered workflows that skip never report, so a required check would block merge. Option A no required checks; Option B one CI workflow with change detection plus an always-running aggregate job that is required. Recommend B
- (question) Does the bot's fine-grained token have Workflows: write? Without it the sandbox cannot push .github/workflows/* and the CI story fails at push
- (decision) Non-goals: deployment and cloud resources; database and migrations; auth and tenancy; logging/telemetry beyond framework defaults; browser E2E (Playwright); UI design, component library, i18n/RTL; app container images; production CORS
- (decision) Companions: adopt ADR-0003, ADR-0005, ADR-0006 (stack and layout live there; not duplicated)
- (decision) Success signal: from a clean clone the page reports the API healthy; every Epic 0 PR came from the sandbox and was merged through the review loop; both CI checks green on main
- (event) Self-validate pass 1 (coherence): PASS. 4 CAPs each with intent+success; constraints each rule something out; 8 non-goals; success signal demonstrable
- (event) Self-validate pass 2 (preservation): PASS. All in-chat scope claims and ADR-0006 test/layout rules landed (kernel or adopted ADR companions). Wrapper-only content: none
- (direction) Developer moved to bmad-ticket without changing the assumptions; they stand. Both open questions (required checks, bot Workflows permission) stay open and gate the CI story
- (decision) Required checks: Option B. One CI workflow detects which side changed and runs only that side's jobs; an aggregate job always runs, fails if any ran job failed, and is the only required check on main (developer, 2026-10-09). Resolves the required-checks open question
- (decision) Bot token is a classic PAT; pushing .github/workflows/* needs its workflow scope. Developer confirms the scope before the CI story starts (hitl on that story). Resolves the token open question
- (decision) Backend tests live in src/backend/tests, not a root tests/backend, so each side is one folder (developer deferred to recommendation, 2026-10-09; ADR-0006 amended). Supersedes the layout line in the stack constraint
- (capability) CAP-5 intent: backend code follows one project style that the build enforces. success: a formatting or naming violation from ADR-0007 fails dotnet build from the root; the existing backend code builds with zero diagnostics and no suppressions (developer, 2026-10-09)
- (decision) Backend style per ADR-0007: reference conventions enforced as build errors; CS0108 and one-type-per-file kept on; frontend keeps CLI defaults; delivered as a new story after 0.1 (developer, 2026-10-09)
