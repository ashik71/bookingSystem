# Progress: #37 (6b) Integration events arrive through the inbox

Scope: 6b only (the consume side on top of #27's outbox).

## Done
- `MongoUnitOfWork`: joined mode (`IsJoined`, `JoinIfOutsideCommit`). The consume outbox's `BeginTransaction` (before the commit starts) joins; the bus outbox beginning a transaction during the commit does not. Joined `CommitAsync` writes aggregates and publishes staged events but leaves the commit to the consume outbox.
- `MongoCommandExecution`: in a joined scope the handler runs once in the caller's scope; a refusal is logged (EventId 11) and returned.
- `SlotBookConsumerDefinition<T>`: explicit endpoint name `{prefix}{module}-{purpose}` via `EndpointNaming` (the prefix is `Messaging:EndpointPrefix`, for tests), interval retry 1/5/15/30 s ignoring DomainException/ValidationFailedException/FormatException/JsonException, inner conflict retry (`WriteErrorClassifier` = RerunHandler, 5 ms doubling to 100 ms, 30 retries, about 3 s), then `UseMongoDbOutbox` at the endpoint. Dedup debug log through `InboxOuterLogFilter`/`InboxInnerLogFilter` (EventId 20).
- Inbox cleanup service stays disabled: it stops the host when MongoDB is down (`HealthEndpointTests.ReadyIs503UnhealthyWhenMongoDbUnreachable` failed with it on). Instead, delivered inbox rows expire through a MongoDB TTL index on `Delivered` (created at startup by `BusOutboxCollection`, `expireAfterSeconds` 1800), from the same constant as `outbox.DuplicateDetectionWindow` (30 min). A failed consume leaves a row without `Delivered`, which TTL skips.
- Tests: `InboxTests`, `ConsumerRetryTests` (own `ConsumerHost`, because the API passes no consumer assemblies), architecture rules `AD-10 integration events` and `AD-10 consumer definitions` with fixtures.

## Decisions
- `UseMongoDbOutbox` exists only at endpoint level, so the retries and the outbox are configured on the endpoint; the fault filter and the inner log filter are consumer filters inside it.
- A failed consume leaves an inbox row (MassTransit inserts it when it takes the lock), so tests assert on the counter, not on "no inbox row".
