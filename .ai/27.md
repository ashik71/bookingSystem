# Progress: #27 (6a) Integration events leave through the outbox

Scope: 6a only, per the approved plan and the split comment. The inbox, joined mode, consumer
definitions, retry rules and the event/consumer architecture rules are 6b.

## Done
- Packages: MassTransit, MassTransit.RabbitMQ, MassTransit.MongoDb 8.5.11 (accepts MongoDB.Driver 3.12.0). `RabbitMQ.Client` pin raised 7.2.0 -> 7.2.2 (MassTransit.RabbitMQ needs >= 7.2.2).
- `TenantEvent` (Contracts), `IUnitOfWork.AddIntegrationEvent<TEvent>`, `EventStamp.Now(IClock)` (Application).
- `MongoUnitOfWork`: stages events, publishes them through the scoped `IPublishEndpoint` (the bus outbox) before the commit; events-only units of work open a transaction; the commit passes `CancellationToken.None`.
- `UnitOfWorkMongoDbContext` replaces MassTransit's scoped `MongoDbContext`: the outbox writes on the unit of work's session (snapshot/majority kept).
- `AddSlotBookMessaging`, `RabbitMqOptions` + validator, `Program.cs` line, `render.yaml` key.
- Bus health check removed from `/health/ready` (MongoDB only).
- Tests: `OutboxTests`, `EventSerializationTests`, `MessagingStartupTests`, `RabbitMqOptionsValidatorTests`; factory options (`RabbitMqConnectionString`, `EndpointPrefix`), `EventRecorder`, `OutboxDrain`.

## Decisions
- `MongoDbContext` assumption holds: it is a public interface, replaceable in DI. No P-5 fallback needed.
- `Session` of the adapter is null until a session starts (MassTransit's delivery service reads before it begins a transaction).
- The inbox cleanup service is disabled in 6a: it creates an index on start and stops the host when MongoDB is down. 6b turns it on.
- MassTransit's scan only sees public consumers.
- Test consumers in 6a are `EventRecorder` endpoints on the bus (auto-delete, non-durable); the broker has one exchange per event type shared by all test hosts, so recorders filter by tenant or event id.
